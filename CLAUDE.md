# SynthOS — notes for Claude

Read `INSTRUCTIONS.md` first (Russian, the full guide), then `docs/ARCHITECTURE.md`.

## Commands

- `make` — build `build/vga/synthos.img` (own bootloader + kernel + ramdisk)
- `make test` — serial-console build, boots in QEMU, runs `tests/run.sh` (must stay at 0 failures; starts local
  HTTPS/cookie servers when `openssl`/`python3` exist)
- `make test-hw` — same image on BIOS/UEFI × IDE/AHCI/NVMe/USB/xHCI and i486 (needs `ovmf`), then installs next to a
  GPT "Windows" partition (UEFI, boot-entry registration) and over a whole disk (BIOS), ~4 min
- `make ARCH=x86_64` — the 64-bit kernel (`build/vga64`, `build/serial64`; any target: `test`, `test-hw`, `usb`);
  arch code in `arch/x86/64/` replaces cpu.c/paging.c/entry/isr/BIOS and AP start-up; no Win32 subsystem yet
  (`CONFIG_WIN32=0`, tests skip Windows cases)
- `make usb` — compact USB-stick image `build/synthos-usb.img` (docs/INSTALL.md is the user guide)
- `make test-crypto` — kernel crypto built for the host, checked against Python `cryptography`
- `make run-uefi` — boot with OVMF firmware (framebuffer console)
- `make run` / `make run-serial` — boot in QEMU (x86_64, 256 MB, e1000 user networking)
- `tests/shot.sh <img> <out.png> <wait-seconds> <qemu keys...>` — VGA screenshot after typing keys
  (the VGA build boots into the desktop; keys go to the Terminal window, `launch <app>` opens apps;
  a key `sleep:N` pauses, `AFTER=N` waits before the shot, `QEMU_EXTRA` adds flags)
- `prof -o file cmd` inside the OS + `tools/profsym.py build/<variant>/kernel.elf < file` — where time goes
- `tools/w32audit.py build/serial/kernel.elf` — every built-in Win32 export must pop the same stack bytes as
  Wine's .spec says (run it after adding exports); Ctrl+T while a Win32 program runs dumps its processes/threads

## Rules

- Everything is from scratch: no Linux, no libc in the kernel, no GRUB. Hardware code lives only in `arch/`.
- Portable kernel talks to hardware only through `include/synth/hal.h`.
- Extend through registration macros: `COMMAND`, `SETTING`, `BINFMT`, `FS_TYPE`, `W32_EXPORTS`, `W64_EXPORTS`,
  `GUI_APP` (linker sections).
- Desktop: `kernel/gui/` (gfx, wm, ui toolkit, menubar, dock, desktop, terminal), apps in `kernel/gui/apps/` use
  `ui_run` frames, colors only from `style`, fonts `font_sans/bold/title/mono`. `uifont.c`/`icons.c` are generated by
  `tools/mkuifont.py`/`tools/mkicons.py` — edit the scripts, not the output. The event loop is a cooperative
  input pump (`input_set_pump`); never call it from IRQ context.
- Win32 API: stdcall functions in `kernel/win32/`, msvcrt (cdecl) in `kernel/win32/crt/`; per-process globals get
  `W32_STATE`; floating point only in `*_fp.c` files. Win64 reuses the 32-bit functions through `W64_EXPORTS`
  tables in `win64*.c` (flags or a translating handler).
- Network: drivers fill `struct netdev`; HTTP(S) in the kernel goes through `http_fetch` (`synth/http.h`),
  HTML through `html_parse` (`synth/html.h`).
- The kernel code must stay below 3.5 MiB (`kernel_end < 0x380000`): put big tables on the heap. The ramdisk is a
  separate pack after the image (`mkrd --kernel`), loaded into the heap; kernel.bin + pack must fit the 4 MiB ESP.
- Commands print via `sh_printf`/`sh_puts` to `sh->out`, colors only via theme roles (`sh_role`).
- Errors are negative `E_*` codes. C11 (gnu11), 4 spaces, very few comments, `module_action` names.
- Build must be warning-free; add a test case to `tests/run.sh` for new behavior.
- Measure before and after when optimizing (`time`, `prof`, `winbench`).
- User-facing docs are in Russian; in-OS text is English (the VGA font is CP437).
